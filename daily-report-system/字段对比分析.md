## 四、字段命名不一致总结

### 核心问题

前端使用**驼峰命名** (camelCase)，数据库使用**蛇形命名** (snake_case)。

| 数据库 (snake_case) | 前端 (camelCase) | 工具 schema (camelCase) | 状态 |
|-------------------|-----------------|----------------------|------|
| area_id | areaId | areaId | ✅ 前后/工具一致, DB 不同 |
| plan_id | planId | planId | ✅ 前后/工具一致, DB 不同 |
| completion_type | completionType | - | ✅ 前后一致 |
| building_no | buildingNo | - | ✅ 前后一致 |
| floor_no | floorNo | - | ✅ 前后一致 |
| voice_text | voiceText | - | ✅ 前后一致 |
| start_date | startDate | - | ✅ 前后一致 |
| end_date | endDate | - | ✅ 前后一致 |
| task_name | taskName | taskName | ✅ 前后一致 |
| total_man_days | totalManDays | - | ⚠️ 工具schema未定义 |
| labor_schedule | laborRequirements/laborSchedule | - | ⚠️ 不一致 |
| propose_dept | proposeDept | - | ✅ 前后一致 |
| cooperate_dept | cooperateDept | - | ✅ 前后一致 |

### 关键发现

1. **前端 ↔ 工具 schema 命名完全一致**（都是驼峰）✅
2. **前端 ↔ 数据库表字段命名不一致**（驼峰 vs 蛇形）— 通过 API 层做映射
3. **后端 payload JSONB 层**使用驼峰命名，与前端一致 ✅
4. **顶层字段**（owner/type/status/time）前后端一致 ✅

## 五、缺失/不一致字段详细清单

### 🔴 严重 (可能导致数据丢失或不一致)

1. **计划表缺少 builder_no/floor_no/owner/process 字段持久化**
   - 前端显示和编辑了这些字段
   - DB 无对应列
   - 写入时不会持久化
   - **影响**: 刷新页面后这些字段的编辑值丢失

2. **payload 中的 headcount 计算逻辑不一致**
   - 前端: `event.payload.headcount = laborRequirements.reduce(...)` 自动计算
   - 后端 createEvent: 直接读取 `data.headcount` 写入 payload
   - **影响**: LLM 录入时 headcount 是用户传入还是自动计算?

### 🟡 中等 (需要注意)

3. **updateEvent handler 的 areaId 处理**
   - handler 从 `data.areaId` 读取 → 写入 `payload.areaId`
   - 但 DB 的 `dr_events.area_id` 是独立列，不在 payload 里
   - **影响**: 更新 areaId 时可能只更新了 payload 而未更新顶层 area_id 列

4. **issue 表部分字段未暴露前端编辑**
   - `priority`, `deadline`, `description`, `resolution`, `photos` 都在 DB 中
   - 前端编辑表单只包含 `title`, `proposeDept`, `cooperateDept`
   - **影响**: 这些字段只能通过 LLM 或数据库操作修改

5. **comparePlansVsActuals 工具未定义**
   - 在 llm-tools.js 中引用了 comparePlansVsActuals
   - 但需要确认 schema 中是否包含所有必要字段

### 🟢 轻微 (仅命名风格)

6. **全局命名规范**: 前端和工具 schema 都用驼峰，DB 用蛇形 — 在 API 层做映射即可，不碍事

## 六、建议

### 优先级 1: 修复计划表缺失字段
```sql
ALTER TABLE dr_daily_plans ADD COLUMN IF NOT EXISTS process TEXT;
ALTER TABLE dr_daily_plans ADD COLUMN IF NOT EXISTS owner TEXT;
ALTER TABLE dr_daily_plans ADD COLUMN IF NOT EXISTS building_no TEXT;
ALTER TABLE dr_daily_plans ADD COLUMN IF NOT EXISTS floor_no TEXT;
```
然后在 `updatePlan` handler 中写入这些字段。

### 优先级 2: 统一 updateEvent 的 areaId 写入
当前 `updateEvent` 从 `data.areaId` 读取后应该同时更新 `dr_events.area_id` 顶层列和 `payload.areaId`。

### 优先级 3: 补充 issue 编辑表单
至少应该暴露 `priority` 和 `deadline` 给前端。

### 优先级 4: 制定字段命名规范文档
- DB 层: snake_case (已遵守)
- API/JSON payload: camelCase (前端+工具 schema)
- 映射层: 统一在 API 响应中做 snake → camel 转换
